# Project Documentation Outline

## Problem Statement

Urban traffic systems produce large volumes of time-dependent and location-dependent data. A useful academic system must store this data efficiently, support spatial and relational analytics, represent road connectivity, and provide a forecasting layer.

## Objectives

1. Design a normalized relational traffic database.
2. Add spatial capabilities through PostGIS.
3. Represent the road network using Neo4j.
4. Demonstrate indexing, joins, aggregation and query optimization.
5. Build traffic analytics and congestion alerts.
6. Integrate a GCN for short-horizon traffic forecasting.
7. Expose the data through FastAPI and React.

## Existing System

Traditional implementations may store traffic information in tables without making spatial or graph relationships first-class concepts. This project combines relational, spatial and graph database approaches.

## Proposed System

PostgreSQL is the system of record. PostGIS handles geometry and spatial operations. Neo4j provides road-network traversal. The ML layer uses historical traffic features and graph connectivity for GCN forecasting. Predictions are stored back in PostgreSQL for application reporting.

## Algorithms

### Congestion classification

A demonstration rule maps predicted/observed volume into LOW, MEDIUM, HIGH and SEVERE categories. These thresholds are configuration values for the academic demo and are not claims about real-world traffic standards.

### GCN

The first GCN uses four lagged traffic-volume values as node features and road connectivity as graph edges. A held-out temporal portion of the synthetic dataset is used for evaluation.

### Baseline

Linear Regression uses the same four-lag feature window so that the comparison is meaningful.

## Evaluation

Use MAE, RMSE and MAPE. Report only values generated by `ml/training/train_gcn.py`.

## Performance considerations

- Composite time-series index on `(sensor_id, recorded_at)`
- GiST indexes for PostGIS geometry
- Views for repeated current/junction analytics
- Parameterized SQL through SQLAlchemy
- Pagination/limits on history endpoints
- Graph traversal through Cypher rather than recursive relational joins for graph-specific tasks

## Future Scope

- Replace synthetic records with METR-LA or another documented public dataset.
- Add GAT after the GCN baseline is stable.
- Add streaming ingestion from real sensors.
- Add richer road attributes and weather features.
- Add authenticated analyst/admin roles only if required by the course.
